## Issue #13: Image Upload Interface Missing (CRITICAL)

**Reporter:** yxk9810 | **Opened:** Jan 13, 2026
**Error:** `Error calling extension 'LoadExrLayerByName' method 'setup'`

**Root Cause Found:** `js/load_exr_layer_by_name.js` has a variable scope bug in the `setup()` method (lines 240-271). The variable `isCryptomatte` is referenced in `setup()` but it's only defined inside the `beforeRegisterNodeDef` callback scope. When ComfyUI calls `setup()` globally, it throws a `ReferenceError`, which cascades and breaks core ComfyUI functionality including image uploads.

**Additionally:** `js/index.js` line 3 imports `"./load_exr.js"` which does not exist in the `js/` directory. This missing import would also cause the entire JS extension bundle to fail to load.

**Fix needed:**
1. Remove the non-existent `import "./load_exr.js"` from `js/index.js`
2. Refactor `setup()` to find both node types directly instead of relying on the out-of-scope `isCryptomatte` variable

## Issue #10: EXR 32-bit Saves as 16-bit (HIGH)

**Reporter:** adrientoupet | **Opened:** Nov 10, 2025

**Root Cause Found:** Two compounding problems:

1. **JS failure prevents widget creation** — Because `js/index.js` fails (missing `load_exr.js` import), the dynamic format widgets from `js/saver.js` never load, so the `bit_depth` parameter is never sent to Python.

2. **Python fallback defaults to wrong value** — In `modules/saver.py:281-282`, when `bit_depth` is `None`, the fallback hardcodes `"16"` for EXR files, contradicting the UI definition at line 60 which correctly sets the default to `"32"`.

**Fix needed:**
1. Fix the JS import issue (same as #13)
2. Change the fallback in `saver.py` to default EXR to `"32"` to match the declared UI default

## Issue #8: Colorspace Conversion Runs Every Execution (RESOLVED)

**Reporter:** TheArtOfficial | **Opened:** Oct 5, 2025

**Status: Already fixed.** Both `ColorspaceNode` and `ZNormalizeNode` now implement smart caching in their `IS_CHANGED` methods — they hash tensor properties, parameters, and pixel samples instead of returning `float("NaN")`. The fix is in the current codebase. The only remaining optimization opportunity is `ImageLoader`, which still uses `NaN` and could benefit from file-based caching like `LoadExr`.

## Issue #4: Dynamic Subfolders (FEATURE REQUEST)

**Reporter:** Nekodificador | **Opened:** May 30, 2025
**Request:** Support patterns like `Maps/%date:dd-MM-yyyy%/depth_0001`

**Current state:** The `file_path` parameter in `saver.py` is treated as a literal directory path with zero template substitution. Only `####` frame patterns in filenames are supported.

**What's needed:** A template variable substitution system supporting `%date:format%`, `%time:format%`, `%frame%`, etc., integrated at the path-building stage around `saver.py:315-321`. This is a net-new feature.
